# moex-portfolio

Сервис для учёта инвестиционного портфеля на данных Московской биржи.
Хранит портфели и позиции в PostgreSQL, а текущую стоимость и доходность
считает по котировкам из публичного [ISS API Мосбиржи](https://iss.moex.com).

Учебный pet-проект на Go: в коде много комментариев с параллелями из Java/Spring.

## Возможности

- Портфели и позиции: тикер, количество, средняя цена покупки.
- Оценка портфеля по текущим котировкам: стоимость, прибыль/убыток, доходность
  в процентах — по каждой позиции и по портфелю в целом.
- Деньги считаются точно (`numeric` в БД, `decimal` в Go), без `float`.
- Если ISS недоступен, портфель всё равно отдаётся — просто без оценки.
- Миграции схемы применяются автоматически при старте.

## Быстрый старт

Нужен **Docker** с Compose. Одна команда поднимает PostgreSQL и сервис:

```bash
docker compose up -d --build
```

Сервис слушает `http://localhost:8080`, миграции применяются при старте. Проверка:

```bash
curl localhost:8080/healthz
# ok
```

| Команда                          | Что делает                                     |
|----------------------------------|------------------------------------------------|
| `docker compose ps`              | Статус контейнеров                             |
| `docker compose logs -f app`     | Логи сервиса                                   |
| `docker compose up -d --build`   | Пересобрать образ после изменений в коде       |
| `docker compose down`            | Остановить всё (данные сохранятся)             |
| `docker compose down -v`         | Остановить и удалить базу вместе с данными     |

### Режим разработки

Для работы над кодом удобнее держать в Docker только базу, а сервис
запускать с хоста — перезапуск за секунду, без пересборки образа.
Нужен **Go 1.26+**.

```bash
docker compose up -d postgres     # только база
go run ./cmd/server               # сервис с хоста
```

Если перед этим был запущен весь стек, сначала остановите контейнер сервиса
(`docker compose stop app`), иначе порт 8080 будет занят.
Остановка сервиса, запущенного через `go run` — `Ctrl+C`.

### Пример за минуту

```bash
# создать портфель
curl -X POST localhost:8080/portfolios -d '{"name":"Долгосрочный"}'

# добавить позиции
curl -X PUT localhost:8080/portfolios/1/positions/SBER -d '{"quantity":10,"avg_price":"250.50"}'
curl -X PUT localhost:8080/portfolios/1/positions/GAZP -d '{"quantity":100,"avg_price":"130"}'

# посмотреть стоимость и доходность
curl localhost:8080/portfolios/1
```

Готовый набор запросов для HTTP-клиента GoLand / IntelliJ IDEA —
[`examples/requests.http`](examples/requests.http).

## Настройки

Все настройки — через переменные окружения. Значения по умолчанию рассчитаны
на локальный запуск через `go run` с базой из `docker-compose.yml`; контейнеру
сервиса compose сам передаёт `DATABASE_URL` с хостом `postgres`.

| Переменная     | По умолчанию                                               | Назначение                |
|----------------|------------------------------------------------------------|---------------------------|
| `HTTP_ADDR`    | `:8080`                                                    | Адрес HTTP-сервера        |
| `DATABASE_URL` | `postgres://moex:moex@localhost:5432/moex?sslmode=disable` | Подключение к PostgreSQL  |
| `ISS_BASE_URL` | `https://iss.moex.com/iss`                                 | Корень ISS API Мосбиржи   |

## API

| Метод    | Путь                                    | Описание                              |
|----------|-----------------------------------------|---------------------------------------|
| `GET`    | `/healthz`                              | Сервис жив и база доступна            |
| `POST`   | `/portfolios`                           | Создать портфель                      |
| `GET`    | `/portfolios`                           | Список портфелей                      |
| `GET`    | `/portfolios/{id}`                      | Портфель с позициями и оценкой        |
| `PUT`    | `/portfolios/{id}/positions/{ticker}`   | Создать или заменить позицию          |
| `DELETE` | `/portfolios/{id}/positions/{ticker}`   | Удалить позицию                       |

**Общие правила**

- Тело запроса и ответа — JSON. Неизвестные поля в запросе — ошибка `400`
  (защита от опечаток вроде `"nmae"`).
- Денежные значения в ответах — **строки** (`"250.5"`), чтобы клиенты
  не теряли точность на `float`. Незначащие нули отбрасываются: `"12.8"`, а не `"12.80"`.
  На входе цена принимается и строкой, и числом.
- Суммы в рублях (`cost`, `market_value`, `pnl`) округляются до копеек,
  проценты — до сотых. Цены выводятся как есть.
- Время — в формате RFC 3339.

### Создать портфель

```http
POST /portfolios
{"name": "Долгосрочный"}
```

```http
HTTP/1.1 201 Created
Location: /portfolios/1

{"id": 1, "name": "Долгосрочный", "created_at": "2026-10-06T19:25:24.580854+03:00"}
```

Имя — от 1 до 100 символов, пробелы по краям обрезаются.

### Добавить или изменить позицию

```http
PUT /portfolios/1/positions/sber
{"quantity": 10, "avg_price": "250.50"}
```

```json
{
  "ticker": "SBER",
  "quantity": 10,
  "avg_price": "250.5",
  "updated_at": "2026-10-06T19:25:24.593107+03:00"
}
```

- `PUT` полностью заменяет позицию: повторный запрос с тем же тикером
  перезапишет количество и цену (а не добавит к ним).
- Тикер приводится к верхнему регистру: `sber` → `SBER`. Допустимы латиница и цифры, до 20 символов.
- `quantity` — количество **штук** (не лотов), больше нуля.
- `avg_price` — средняя цена покупки за штуку в рублях, обязательна, `>= 0`.

| Поле                      | Значение                                                            |
|---------------------------|---------------------------------------------------------------------|
| `valuation.current_price` | Текущая цена за штуку                                               |
| `valuation.cost`          | Вложено: `avg_price × quantity`                                     |
| `valuation.market_value`  | Стоит сейчас: `current_price × quantity`                            |
| `valuation.pnl`           | Прибыль/убыток: `market_value − cost`                               |
| `valuation.pnl_percent`   | Доходность: `pnl / cost × 100`; `null`, если `cost = 0`             |
| `valuation: null`         | Для тикера нет котировки — позиция не оценена                       |
| `summary`                 | Итоги **только по оценённым позициям**                              |
| `summary.unpriced`        | Тикеры без котировки; если список не пуст — итоги неполные          |
| `summary.priced_at`       | Время самой свежей котировки                                        |
| `summary: null`           | ISS недоступен — портфель отдан без оценки                          |

### Ошибки

Ошибки возвращаются в едином формате `{"error": "..."}`:

| Статус | Когда                                        | Пример тела                                               |
|--------|----------------------------------------------|-----------------------------------------------------------|
| `400`  | Некорректный JSON или неизвестное поле       | `{"error":"invalid JSON body: json: unknown field \"nmae\""}` |
| `400`  | Не прошла валидация                          | `{"error":"invalid quantity: must be positive"}`          |
| `400`  | Обязательное поле не передано                | `{"error":"invalid avg_price: is required"}`              |
| `400`  | Некорректный `id` в пути                     | `{"error":"invalid id: must be a positive integer"}`      |
| `404`  | Портфель или позиция не найдены              | `{"error":"not found"}`                                   |
| `405`  | Метод не поддерживается для пути             | —                                                         |
| `500`  | Внутренняя ошибка (детали — только в логах)  | `{"error":"internal error"}`                              |
| `503`  | `/healthz`: база недоступна                  | `database unavailable`                                    |

## Как считается оценка

Котировки берутся из ISS для режима торгов **TQBR** (акции и фонды) при каждом
запросе портфеля. Публичные данные ISS **отложены примерно на 15 минут**.

Текущая цена выбирается по первой доступной колонке:

1. `LAST` — цена последней сделки;
2. `LCURRENTPRICE` — официальная текущая цена;
3. `MARKETPRICE` — рыночная цена по методике биржи;
4. `PREVPRICE` — цена закрытия предыдущего дня.

Бумаги, которых нет на TQBR (например, облигации), не оцениваются и попадают
в `summary.unpriced`. На запрос котировок отводится 3 секунды; при ошибке или
таймауте портфель отдаётся без оценки, а в лог пишется предупреждение.

## Структура проекта

```
cmd/server/          точка входа: конфиг, сборка зависимостей, HTTP-сервер
internal/
  config/            настройки из переменных окружения
  postgres/          пул соединений pgx
  db/                код запросов, сгенерированный sqlc (+ queries/*.sql)
  portfolio/         портфели: handler → service → repository, расчёт оценки
  moex/              HTTP-клиент к ISS API
  quote/             (план) фоновая загрузка котировок и история
migrations/          SQL-миграции goose, встроены в бинарник
examples/            готовые HTTP-запросы
Dockerfile           многоэтапная сборка: golang → distroless (~20 МБ)
docker-compose.yml   PostgreSQL + сервис
```

## Разработка

```bash
# тесты (с детектором гонок)
go test -race ./...

# статический анализ
go vet ./...
go run honnef.co/go/tools/cmd/staticcheck@latest ./...
```

**SQL-запросы.** Запросы лежат в `internal/db/queries/*.sql`, Go-код по ним
генерирует [sqlc](https://sqlc.dev). Он подключён как tool-зависимость модуля,
отдельно ставить не нужно:

```bash
go generate ./...     # после изменения запросов или миграций
```

Сгенерированный код коммитится вместе с запросами.

**Миграции.** Новая миграция — файл `migrations/0000N_<название>.sql`
с секциями goose `Up` и `Down` (см. `00001_init.sql`). Создать заготовку:

```bash
go run github.com/pressly/goose/v3/cmd/goose@v3.28.0 -dir migrations -s create add_something sql
```

Миграции применяются при следующем запуске сервиса. Важно: goose разбирает
любой SQL-комментарий, содержащий его аннотацию, поэтому в обычных
комментариях миграций её писать нельзя.

## Ограничения и планы

- Оцениваются только акции и фонды режима TQBR; облигаций пока нет.
- Котировки запрашиваются при каждом просмотре портфеля, без кэша.
- Тикер при добавлении позиции проверяется только по формату, не по наличию на бирже.
- Учёт отдельных сделок с пересчётом средней цены — в планах.
- Фоновая загрузка котировок и свечей с хранением истории (`internal/quote`) — в планах.
- Интеграционные тесты репозитория на testcontainers — в планах.
